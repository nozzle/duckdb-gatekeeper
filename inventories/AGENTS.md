# Function policy inventories

When changing inventories or their audit/generation tooling:

- Types, casts, and collations are host-trusted; they have no runtime allowlist or mandatory inventory audit. Preserve generic checks on executable bind-time expressions, including type parameters.

- Default functions are a name-based convenience list. Existing DuckDB implementations are trusted across upgrades; implementation changes under existing names are not a backwards-compatibility attack model. New names remain excluded unless explicitly allowed or added to defaults.
- When adding or changing a classification, inspect the relevant function registrations, parser rewrites, and macro bodies and record the source used. Use `duckdb_functions()` to discover changes and cross-check coverage, never to generate an allowlist automatically.
- Keep function names lowercase, sorted, unique, and grouped by the serialized `function_name`. Review side effects, volatility, resource I/O, dynamic SQL/dispatch, catalog/session access, and macro/type/name collisions. A name is authorized across signatures: classify it by its most capable overload.
- Put reviewed local computation or embedded static data in `compute`. Reading the clock (transaction start or execution time), non-cryptographic PRNG state (the connection-local engine, query-local engines, and `setseed`'s reseed of the connection engine), or the `TimeZone`/`Calendar` settings that every ICU temporal function consumes is compute; see the criteria in README.md. Put resource access, other mutation, dynamic dispatch, catalog/session/configuration/planner inspection, caller-supplied-name catalog resolution, bind-time evaluation of caller expressions without a foldability check, resource consumption (`sleep_ms`), raw-pointer arguments, internal/debug/test registrations, and source-limited runtime-verified names in `elevated`. Treat other volatility as elevated unless the exact pinned source shows it reads nothing but its arguments and those admitted sources. Keep uncertain or unaudited names in `unreviewed`; both elevated and unreviewed names are excluded from defaults. Registered aliases must share their canonical name's classification.
- Keep core grouping in `core.json` consistent with its compute list. Keep extension classifications, source pins, and non-obvious review reasons together in `extensions/<duckdb-extension-id>.json`. Do not discard review notes when restructuring data.
- Inventory source revisions and `reviewed_duckdb` record historical provenance, independently of the engine used to build Gatekeeper. Preserve them until classifications are actually reviewed again. A newer engine or changed extension descriptor must not block generation.
- Runtime signature comparisons report additions, removals, and changes for maintenance. They are not engine compatibility gates and do not require re-reviewing existing names on each patch or minor release. Review optional extensions when extending their default coverage, recording actual sources and runtime limitations.
- Capture candidate snapshots separately from historical baselines. Never replace a baseline merely to suppress a report, or mark a version reviewed without completing that review. Document unavailable extensions and incomplete runtime coverage; the Python baseline is not a complete extension audit.
- Verify parser-generated operators, syntax helpers, and reviewed macros with both serialized SQL and executable SQL, since some names have no runtime catalog row. Explain source-backed exceptions rather than weakening audit checks broadly.
- Preserve source-only/runtime-only limitations, especially proprietary inventories such as MotherDuck. Function policy governs explicit caller-authored names; it does not authorize all binding-time behavior, loading, settings, replacement scans, or resources. Trusted attached-table implementations may use internal readers, and there is intentionally no reader-argument inventory.
- Run `python scripts/generate.py`, `python scripts/audit_inventory.py`, rebuild the extension, and run the full test suite after inventory changes. Update tests for intentional default-count changes and add focused policy regressions. Build-engine compatibility is established by compilation and functional regressions, including unsupported-structure handling, not an exact engine pin.

See [README.md](README.md) for commands and the version-update procedure. Gatekeeper's reviewed inventories are canonical; external inventories are evidence, never automatic replacements.
